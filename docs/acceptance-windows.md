### 合成现场

合成根放在本仓库忽略的 `.scratch/issue20-cases/`，五案：

- 甲、乙、丙：loo0ng-skills `54774d00b02e15d552258869f80663537c20cec2` 的 `scripts/skill-eval.py --materialize` 回放「在办中」「两份待确认」「空图」三个种子，回放时设 `PYTHONDONTWRITEBYTECODE=1`，没改那个仓库。
- 丁（看矩阵视的极端列数）：用官方图引擎 CLI 先建一份 30 个模块的合成预设图，再 `init --preset` 起一个案件图，然后 `generate` / `confirm` / `not-applicable` 造出节点状态；第 5 个模块是空模块，第 7 个整块不适用，另有几个节点带长时限。文书一律复制种子里那份带黄色高亮的合成件，所以已生成、已确认的节点高亮都是「未清」。
- 戊（看少模块）：同样的做法，3 个模块。

扫描 CLI 读出五案，没有读不出的，也没有设置错误。丁的节点状态分布：已确认 30、已生成 29、未生成 20、不适用 8；模块状态：进行中 21、已完成 8、不适用 1。

装包按 #20 评论里第 0 步：原包挪到 Zebar 目录之外备份；把 `widget/` 拷成新包并删掉 `__pycache__`；只删 `loo0ng` 一份 WebView 缓存；原设置备份后临时指向合成根。装好的包与 `widget/` 逐文件比对，一致。合成工作区、备份与临时脚本都不提交。

### 本轮命令与检查

```powershell

```
