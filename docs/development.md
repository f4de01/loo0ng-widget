实现规格是 [#2](https://github.com/f4de01/loo0ng-widget/issues/2)，母票是 [#1](https://github.com/f4de01/loo0ng-widget/issues/1)。原型分支只作资料，不合并。

## 包与扫描

`widget/` 是组件包。`scan.py` 是唯一测试缝，完成一层发现、读取和聚合。只支持 Python 3.9 及以上和标准库，没有 Node、JS 测试跑器或类型检查器。

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python -m compileall -q widget tests
python widget/scan.py --根 <合成案件根目录>
python widget/scan.py --设置 <设置文件>
```

`--根` 可重复，提供它就不读取设置。默认设置是 `~/.loo0ng/卡片设置.json`，形状为 `{"根目录":["绝对路径"]}`。

输出沿用 #2 的 `扫描时间`、`设置文件`、`根目录`、`行`、`读不出`；另加顶层 `案件数`（成功读出的案件数）和每行 `待看数`。两个计数由扫描脚本生成，页面不再计算数组长度。用户已确认这一契约补充。案件按目录名 Unicode 升序排列；四档排序属于 #5。

合成视图手写在 `tests/test_scan.py`，测试不调用引擎。两条边界测试分别检查包源码禁用名称和输出不含条目键。检查禁用名称前移除允许的完整文件名，避免把其中的后缀误认成另一个文件名。

## 页面与宿主

把 `widget/` 的内容装到 `~/.glzr/zebar/loo0ng/`，通过 Zebar 的「案件卡片 / 默认」打开。已有安装先备份。`includeFiles` 是资源白名单，新增资源要同步维护。

页面直接按扫描数组顺序渲染。每五秒发起扫描，失败显示错误并保留上一轮内容和时刻；下一轮继续。手动按钮与轮询共享忙碌状态，避免重叠执行。

未识别宿主时直接报错。开发预览要显式访问 `index.html?dev=1`，手动选择扫描 CLI 导出的 UTF-8 JSON；这条通道不轮询，也不替代宿主验收。

开发时改包后若仍看到旧页面，关闭该组件，清理 `%APPDATA%\zebar\webview-cache\loo0ng` 下该包的缓存，再打开。删除前确认实际目录，勿清其他组件缓存。

本票仍采用原型使用的 `zebar@3.3.1` 远程客户端；离线依赖由 #3 处理。完整设置错误指引属于 #4，一条命令安装属于 #6，窗口控件与拖动属于 #7，最终人手验收属于 #8。
