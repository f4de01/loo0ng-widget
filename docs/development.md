# 开发与验证

实现规格是 [#2](https://github.com/f4de01/loo0ng-widget/issues/2)，母票是 [#1](https://github.com/f4de01/loo0ng-widget/issues/1)。原型分支只作资料，不合并。

Windows 首版已通过 #8 最终验收，逐项证据、机器与版本、Python 3.9 跑法及现场恢复情况见 [Windows 验收记录](acceptance-windows.md)。下文保留各实现票当时的验证过程与后续补验。

## 包与扫描

`widget/` 是组件包。测试缝是随包脚本的命令行，共两条：`scan.py` 完成一层发现、读取和聚合，`launch.py` 只找宿主、调一条命令（见下面的 #15 一节）。只支持 Python 3.9 及以上和标准库，没有 Node、JS 测试跑器或类型检查器。

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python -m compileall -q widget tests
python widget/scan.py --根 <合成案件根目录>
python widget/scan.py --设置 <设置文件>
```

`--根` 可重复，提供它就不读取设置。默认设置是 `~/.loo0ng/卡片设置.json`，形状为 `{"根目录":["绝对路径"]}`。

输出沿用 #2 的 `扫描时间`、`设置文件`、`根目录`、`行`、`读不出`；另加顶层 `案件数`（成功读出的案件数）和每行 `待看数`。两个计数由扫描脚本生成，页面不再计算数组长度。用户已确认这一契约补充。

#5 的案件排序由脚本完成：有待看、有前方、空图、没有前方四档；同档按系统 `zh_CN.UTF-8` 中文排序，目录名相同时再按路径固定顺序，不按生成时间。没有中文 locale 时明确报错，不静默退回 Unicode 序。Windows 的 Python 3.9.25 已验证；mac 的系统排序仍待交付验收。

清单页每行三层，行不再展开：目录名与「已确认 / 总数」、分段进度条、「当前模块 › 当前节点」。契约见下面的 #14 一节。

合成视图手写在 `tests/test_scan.py`，测试不调用引擎。四条边界测试分别检查包源码禁用名称，以及输出不含条目、不含文书路径、不含前方列表。检查禁用名称前移除允许的完整文件名，避免把其中的后缀误认成另一个文件名。

## 页面与宿主

发布版按 [README](../README.md#装法) 的一条命令安装；本地开发则把 `widget/` 的内容装到 `~/.glzr/zebar/loo0ng/`，通过 Zebar 的「案件卡片 / 默认」打开。已有安装先备份到 Zebar 目录外。

`zpack.json` 的 `includeFiles` 是资源服务器的白名单，不是附带清单。`htmlPath` 指向的文件未被覆盖时，宿主直接回 500。新增资源必须同时加入白名单：当前 `*.html`、`*.css`、`*.js`、`*.py` 覆盖包入口，`vendor/**` 覆盖完整依赖、manifest、说明和许可证。`zpack.json` 是宿主读取的包描述，不是页面请求的资源；安装时仍必须复制它。不要把本机生成的 `__pycache__/` 拷进包里。

页面直接按扫描数组顺序渲染。每五秒发起扫描，失败在顶部压一条横幅并保留上一轮画面；下一轮成功横幅即消失。没有手动扫描按钮，也不显示扫描时刻（#16），轮询用一个忙碌标志避免重叠执行。

未识别宿主时直接报错。不装宿主调样式时，在仓库根目录运行 `python -m http.server 8000 --bind 127.0.0.1 --directory widget`，浏览器打开 `http://127.0.0.1:8000/index.html?dev=1`，在页面里手动选择扫描 CLI 导出的 UTF-8 JSON。用完在终端按 Ctrl+C 停止服务器。这条显式通道不轮询，也不替代宿主验收；不带 `?dev=1` 会明确报未连接宿主。再加 `&blur=1` 把卡片底色切到系统模糊调上时的那一档（60%），只为在调不上模糊的平台上看一眼那层，宿主里不认这个参数。

只用合成案件生成预览 JSON。PowerShell 5.1 的 `>` 默认会写成 UTF-16，可在合成根已准备好后用下面的方式保存（将路径换成你的合成根）：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$preview = python widget/scan.py --根 'D:/合成案件'
if ($LASTEXITCODE -ne 0) { throw '扫描失败' }
New-Item -ItemType Directory -Force .scratch | Out-Null
[IO.File]::WriteAllText((Join-Path $PWD '.scratch/preview.json'), ($preview -join "`n"), [Text.UTF8Encoding]::new($false))
```

开发时每次改包后，先关闭该组件（缓存被占用就退出 Zebar），确认 `%APPDATA%\zebar\webview-cache\loo0ng` 是该包的缓存目录，再清理并重新打开。否则看到的可能还是上一版，包括上一版的报错页。只清 `loo0ng`，勿清其他组件缓存；以后记在 WebView 本地存储里的窗口位置也会随清缓存丢失。

客户端固定为 `zebar@3.3.1`，通过 `vendor/zebar-3.3.1.js` 本地导入；完整浏览器依赖、来源哈希和许可证均随包提供，`vendor/**` 纳入资源白名单。升级步骤见 [随包客户端](../widget/vendor/README.md)。一条命令安装属于 #6，窗口控件与拖动属于 #7，最终人手验收属于 #8。

## #17 全卡可拖

把手从顶行换成整张卡片减去交互区（#12 的窗口裁定，接在 #7 的拖动实现上；#7 的验收记录在下面那节，行为的底子没动）。

**能拖的和不能拖的**：`window.js` 顶上一行 `INTERACTIVE = 'button, input, label, .win-controls, .interactive'` 就是交互区的全部定义。按下时 `event.target.closest(INTERACTIVE)` 命中就当没看见，别的地方一律能拖——透明外边距、顶行、空白、进度条、文字都在「别的地方」里。名单只列卡片今天真有的可点元素：窗口按钮，以及它那一角整块（`.win-controls`——两枚按钮之间那 2px 的缝和容器的留白按下去也不该拖窗，#7 挡的就是这一整块），开发预览那个文件选择器；页面自己画的行与格没有原生语义，靠一个记号类 `.interactive` 进来，今天只有清单页的案件行，**#18 的模块行、节点行与 #19 的矩阵格加上去时记得一并加 `.interactive`**，不然按住它们会拖窗——本仓库不引入 JS 测试跑器，这条约定没有机械守门，只有这行字和 `CONTEXT.md` 的「交互区」一条。行本身若做成原生 `button`，它自己就在名单里，不必再标。

**阈值**：按下先只记一笔（`press`），窗一格都不动；位移过 4 CSS 像素才转成真拖（`drag`），这时才要指针捕获、才开始调 `setPosition`。没过阈值就松手，什么都没发生过，`click` 照常落到按下的那个元素上——所以按下不调 `preventDefault`（它会连带吃掉后面的 `click`）。真拖起来时窗口原点取此刻的位置、位移仍从按下那一点算起，阈值那几像素不丢，全程 1:1 跟手。

**捕获落在 `<html>` 上**：整卡可拖之后按下的那个元素可能是案件行里的一段文字，而清单每五秒重绘一次，按 #7 那样把捕获挂在按下的元素上会在拖到一半时连元素带捕获一起没掉。指针事件因此听在 `window` 上（透明外边距也在里面），捕获挂在 `<html>` 上；`setPointerCapture` 要不到就停在没有捕获的那一档，不影响这一次拖动。失焦、指针取消、按键在窗外松开（下一次 `pointermove` 的 `buttons` 已经是 0）仍然就地结束，最小化与关闭前仍 `settle()` 结算最后一次移动，位置仍只在卡片自己移动成功后写本地存储。

**选中与光标**：全局 `user-select: none` 沿用 #12 的裁定，只给 `input, textarea` 开了例外（开发预览那个选择器，以及日后真出现的输入框）；这条例外不动「设置指引与横幅复制不出来」那一条，要开得先改 #12 的裁定。`touch-action` 全局给 `none`，触屏上一划才不会被当成滚动手势把拖动 cancel 掉；它一给就是整棵树——effective touch-action 要跟祖先求交，`.page` 上再写 `pan-y` 也压不回来，所以触屏上的页内滚动一并关掉了（默认尺寸下三案不溢出，本来也滚不着；鼠标滚轮不走这条路，不受影响）。哪天页内真要触屏滚动，得给把手单独铺一层，不是在 `.page` 上加一行。平时不给 `grab` 光标：能拖的是整张卡，一进窗就换手形反而吵；真拖起来才 `grabbing`（`html.dragging`，规则放在样式表末尾——它和 `.win-controls button` 的 `cursor` 特异度相同，写在前面会被那条盖掉）。顶行的 `id="top"` 随把手一起没了用处，删掉。

- Python 3.9.25：全套 44 条 unittest 通过、零 skip；`compileall` 与 `git diff --check` 通过。本票没动随包脚本，不变量 4 的那条缝没变宽，也没有新增机械测试——页面行为仍不做机械测试（`tests/test_package.py` 的开头写着同一条）。
- 两个页面模块另用 `node --check` 在临时目录的副本上解析过一次（仓库不引入 node，也不引入 JS 测试跑器）。
- 写的时候在临时目录里用 node 搭过一次性的架子探路（最小 DOM 替身 + 假的宿主窗口，走一遍微动当点击、过阈值跟手、交互区不拖窗、窗外松手与失焦结束这几条分支）。**那是探查，不是验收凭据**：架子不提交、不可复现，仓库不引入 JS 测试跑器（不变量 4），拖动仍以真宿主里的人手验收为准。
- **尚待人手验收**（归 #20，在真宿主里看）：Windows 150% 缩放下按住外边距、顶行、空白、进度条、文字拖动是否 1:1 跟手；按住案件行与窗口按钮拖动窗口不动；按下微动后松手当点击（今天案件行还没有点击行为，先看窗口不动、窗口按钮照常生效）；全卡选不中文本；拖到一半赶上一轮重绘不断手；拖动中按住不放时页内滚动条那几像素按下去的是滚动条还是拖窗（Chromium 一般不把原生滚动条的按下发给页面，看一眼确认）。
- 三处已知取舍，一并在真宿主里看一眼：过阈值那一瞬窗口会一次补上按下以来的位移（约 4px），这样抓点始终贴着指针，代价是起手有一跳；`devicePixelRatio` 在起拖时取一次快照，跨不同缩放的显示器拖动会失真（#7 就是这样，整卡可拖之后更容易撞上）；触屏上的页内滚动按上面那条被关掉了。这三条都不在 #17 的验收条款里，遇到再开票。

## #16 外壳与包：材质、尺度、变量、错误现身、去页脚、去 luxon

壳按 ADR-0004 与原型票（#13）的变量表重做，页面仍只有清单页（案件页归 #18）。

**材质**：`zpack.json` 的 `transparent` 打开，默认预设 440×620。页面自绘卡片：`.card` 占满 `inset: var(--margin)`，圆角 18px、底色 `rgba(var(--card-rgb), var(--card-alpha))`、细描边 + 内高光 + 柔投影，投影落在那圈 12px 透明边距上。边距仍是页面的一部分，点得到、拖得动，不穿透到桌面。系统模糊按 ADR-0004 的裁定接在 `window.js` 的 `MATERIAL` 表上：调上了才把 `html[data-blur="1"]` 打开、底色从 90% 降到 60%，抛错就一言不发停在自绘层，只试一种效果，不按「哪个成功用哪个」去探。一个平台一行：**Windows 没有行**——Acrylic 会把整个窗口矩形连同圆角外的四个角磨砂成一块方板，#13 看过截图后裁定不要，所以 Windows 上一次都不调，卡片停在 90% 的自绘层。**mac 那一行是 `underWindowBackground` + `state: 'active'` + 跟着 `--radius` 走的圆角**：这一层是「窗内容背后那一层」，随系统外观走，radius 让磨砂贴住卡片的圆角而不从圆角外冒出来，`active` 是因为这张卡常驻桌面、基本不是活动窗，材质不能跟着失焦一起淡掉。**这一行尚未在 mac 实机上看过**：按 ADR-0004 同一条标准，若它同样盖满整个窗口矩形、或压不住浅色卡片，由 mac 交付票把这一行删掉（删掉即回到自绘那层，别处不用动）；`setEffects` 不抛错但没效果的情形页面无从得知，只能靠一行只试一种把它压到最小。Windows 上 60% 那一档只有 `?dev=1&blur=1` 的模拟能看到，那条路还会自己加一层 `backdrop-filter` 充当桌面模糊，真调上系统模糊时页面不叠这一层。

**变量**：颜色、间距、圆角、字号全在 `style.css` 的 `:root` 里，取值来自原型票的 A 纸那一套（含五态编码与进度条四段的配色）；字体栈补上 `-apple-system, "PingFang SC"`；正文 13px、次要 12px、最小 11px；不做深色模式，以后改的是这一组值。

**尺度与滚动**：卡片内顶行固定、`.page` 页内滚动，窗不自动长高；滚动条用 `scrollbar-width: thin` 加透明的 `scrollbar-color`，悬浮才把滑块染出来，不占一条常驻的灰边。照抄原型的做法，代价说清楚：Chromium 的 `thin` 是经典滚动条，内容真溢出时它仍占那几像素的宽，只是平时被染成透明，不是内容从它底下穿过的那种覆盖式。默认尺寸下三案不溢出，一条滚动条都不出现（#10 顺带看到的那条常驻灰边就是这么没的）；要不要换成自绘的覆盖式滑块，留给 #20 在真窗口里看过再说。窗口按钮平时 `opacity: 0`，鼠标进卡片或键盘走到才显，Windows 右上、mac 左上，顶行给它那一角留出内边距。

**错误现身**：设置错误时顶上的计数一并收起，整页只剩那段可照做的指引；读不出仍排在案件之后，暗色行只写目录名与原因；一轮扫描失败在顶部压一条横幅，下一轮成功即消失，中间画面保留。页脚、扫描时刻、「扫一次」按钮都去掉了，`?dev=1` 的开发预览通道留着。

**拖动**：顶行是这一版的把手（原来是 `<header>`，它随页脚一起没了）。整卡可拖是 #17，那票会把把手换掉。

**去 luxon**：esm.sh 的 zebar bundle 把 luxon 的 10 个模块外部化后逐一导入，9 个没人用，第 10 个只被 zebar 的 `date` provider 用一句，而这张卡片不用 provider。删掉那 10 条导入与对应文件、许可证、manifest 条目，`date` provider 那一句改成抛错说明；随包 SHA-256 重算记进 manifest，上游那份不动。细节与升级时的注意见[随包客户端](../widget/vendor/README.md)。包内文件从 34 个减到 23 个。

**新的测试文件**：`tests/test_package.py` 把原先人手跑的那串检查落成测试——白名单覆盖每个包内文件、包内文件名全 ASCII、manifest 条目与随包字节的 SHA-256 一一对上、所有静态导入都落在包内、luxon 不留痕、`transparent` 与 440×620、页脚与「扫一次」不在。页面行为仍不做机械测试（不变量 4）。

- Python 3.9.25：全套 44 条 unittest 通过、零 skip（新增 8 条）；`compileall` 与 `git diff --check` 通过。新增的三条先在改之前的树上跑红，再转绿。
- 页面的三个模块另用 `node --check` 做过一次语法解析（临时目录里的副本，仓库不引入 node，也不引入 JS 测试跑器）。
- 改包之后记得按上面「页面与宿主」那条清 `%APPDATA%\zebar\webview-cache\loo0ng` 再开：这一轮换了 `index.html` 的骨架与 `style.css` 的整套变量，缓存没清会看到上一版的壳，包括上一版的报错页；清缓存会一并丢掉记在本地存储里的窗口位置。
- 材质、滚动条、窗口按钮、三种错误现身、默认尺寸下没有常驻滚动条这几项，归 Windows 人手验收（#20）在真宿主里逐项看，本票不代跑。
- 双轴审查（标准 / 规格）各跑一遍，据此改了五处：`window.js` 里那条守卫还写着旧类名 `.window-controls`（今天只是死代码，#17 把把手换成整卡之后会变成「点最小化＝拖窗」）；进度条不再靠 `[style="flex-grow: 0;"]` 这种内联样式字符串藏起 0 段，改成那一段干脆不画、空图留一条空槽；mac 的红绿灯恢复成悬停才现出 − 与 ×（原型里那句 `font-size: 0` 会把字形永久抹掉）；`backdrop-filter` 收进模拟档；`MATERIAL` 的 mac 那一行换掉了初版的 `hudWindow`（HUD 是深色材质，与浅色卡片和「不做深色模式」对不上）。没照做的两条记在这里：设置指引与横幅仍受全局 `user-select: none` 管，路径复制不出来——#12 的窗口裁定就是全局禁选，要开例外得先改那条；`扫描时间` 仍由扫描脚本出、已经没有消费方，等契约那一轮再收。

## #15 唤起脚本与 README 三入口

不变量 4 改了措辞：**测试缝是随包脚本的命令行**，现在有两条——`scan.py` 一个人做完发现、读、聚合与显示串格式化，`launch.py` 只找宿主、调一条命令。页面仍然只渲染，不计数、不排序、不取第一个、不算日期。两条缝都不引入 node，也不引入 JS 测试跑器。

`launch.py` 按 ADR-0001 办：PATH 里的 `zebar` 优先，没有就按平台挨个看固定路径（mac `/Applications/Zebar.app/Contents/MacOS/zebar`，Windows `C:\Program Files\glzr.io\Zebar\zebar.exe`），找到即以子进程调

```
<宿主> start-widget-preset --pack loo0ng --widget-name 案件卡片 --preset 默认
```

并透传子进程的退出码；都找不到就在 stdout 印一句「没找到 Zebar……」并退 1。脚本不做任何「带到前面」：宿主对已开着的预设无事发生，还原只能走任务栏 / 程序坞。

```powershell
python -m unittest discover -s tests -p 'test_launch.py'
python widget/launch.py
python widget/launch.py --平台 darwin --固定路径 'darwin=/tmp/zebar'
```

**测法**：`tests/test_launch.py` 只走命令行，起子进程跑 `launch.py`，不导入它的函数。假宿主是临时目录里一个把收到的参数写成 JSON、再按给定码退出的可执行文件（POSIX 上是 `zebar` 这个 `#!/bin/sh` 脚本，Windows 上是 `zebar.bat`，两边都转调本次的 `sys.executable`）。两个测试注入口：

- PATH 整个换成测试自己的目录，所以「PATH 里有 / 没有」两种情形都由测试说了算。
- `--固定路径 平台=路径` 可重复，给了就整张固定路径表都换成注入的，再按 `--平台` 选那一列。这样「按平台、按顺序找」有测试守，而两个真实安装路径的字面值不进测试——**测试一次都不许碰本机真装的 Zebar**，否则会在跑测试时把卡片开出来。那两个字面值由 Windows 人手验收（#20）和 mac 交付票守。

**白名单**：`launch.py` 不需要被资源服务器服务（它不是页面请求的资源），但放在包目录里随 README 那一条安装命令走。现有 `includeFiles` 的 `*.py` 本来就覆盖它，不用改 `zpack.json`；`privileges.shellCommands` 也不用动——那是页面调扫描脚本的口子，唤起脚本从卡片外面跑。

## #21 当前模块改成当前节点所在的模块

## #14 扫描契约扩展与清单页三层行

按 #12 的实现裁定扩了扫描输出，每案多两样：

- `模块[]`：每模块带 `标题`、`状态`、`进度`（未生成 / 已生成 / 已确认 / 不适用 / 总数）、`节点[]`；空模块留在数组里，只是节点为空。
- `节点`：`标题`、`状态`、`高亮`，引擎写了时限就带 `时限`；已确认带确认时刻、已生成带生成时刻，未生成与不适用两档一个时间字段都不带。时间给两份：`时间` 是引擎那串 ISO 原文，`时间显示` 是预先格式化好的「9月21日」，跨年才带年（「2019年1月5日」）。跨年按扫描那一刻的年份判，页面照印，不算日期。

## #7 窗口行为

`window.js` 使用随包客户端的当前组件和 Tauri 窗口接口；启动时加载模块并恢复位置后启用控件。按住表头用同步的 `pointerdown` 开始拖动（对应鼠标按下，增加指针捕获以免快速拖出窗口时丢失事件），按屏幕 CSS 位移乘 `devicePixelRatio` 转为物理位置。`requestAnimationFrame` 合并待移动位置，宿主调用逐次完成，松手、失焦或指针取消时结束拖动；最小化、关闭前处理完最后一次移动。

唯一持久化内容是 WebView `localStorage` 中的 `loo0ng.window-position` 坐标；只在卡片主动移动成功后保存，系统最小化报告的位置不覆盖它。缺失、无效或不可读的存储使用预设位置；存储不可写不影响本次拖动。清 WebView 缓存后回到预设。窗口错误单独显示，不被扫描刷新清除。
