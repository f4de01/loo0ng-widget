# 开发与验证

实现规格是 [#2](https://github.com/f4de01/loo0ng-widget/issues/2)，母票是 [#1](https://github.com/f4de01/loo0ng-widget/issues/1)。原型分支只作资料，不合并。

## 包与扫描

`widget/` 是组件包。`scan.py` 是唯一测试缝，完成一层发现、读取和聚合。只支持 Python 3.9 及以上和标准库，没有 Node、JS 测试跑器或类型检查器。

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python -m compileall -q widget tests
python widget/scan.py --根 <合成案件根目录>
python widget/scan.py --设置 <设置文件>
```

`--根` 可重复，提供它就不读取设置。默认设置是 `~/.loo0ng/卡片设置.json`，形状为 `{"根目录":["绝对路径"]}`。

输出沿用 #2 的 `扫描时间`、`设置文件`、`根目录`、`行`、`读不出`；另加顶层 `案件数`（成功读出的案件数）和每行 `待看数`。两个计数由扫描脚本生成，页面不再计算数组长度。用户已确认这一契约补充。

#5 的案件排序由脚本完成：有待看、有前方、空图、没有前方四档；同档按系统 `zh_CN.UTF-8` 中文排序，目录名相同时再按路径固定顺序，不按生成时间。没有中文 locale 时明确报错，不静默退回 Unicode 序。Windows 的 Python 3.9.25 已验证；mac 的系统排序仍待交付验收。

页面按母票的提示文案区分空图与没有前方，只检查前方是否为空，不计算数量。点击一行展开前方头五个节点，时限原样显示；同时只展开一案，按工作区路径在轮询刷新后保持展开，案件消失则清除展开状态。

合成视图手写在 `tests/test_scan.py`，测试不调用引擎。两条边界测试分别检查包源码禁用名称和输出不含条目键。检查禁用名称前移除允许的完整文件名，避免把其中的后缀误认成另一个文件名。

## 页面与宿主

把 `widget/` 的内容装到 `~/.glzr/zebar/loo0ng/`，通过 Zebar 的「案件卡片 / 默认」打开。已有安装先备份。`includeFiles` 是资源白名单，新增资源要同步维护。

页面直接按扫描数组顺序渲染。每五秒发起扫描，失败显示错误并保留上一轮内容和时刻；下一轮继续。手动按钮与轮询共享忙碌状态，避免重叠执行。

未识别宿主时直接报错。开发预览要显式访问 `index.html?dev=1`，手动选择扫描 CLI 导出的 UTF-8 JSON；这条通道不轮询，也不替代宿主验收。

开发时改包后若仍看到旧页面，关闭该组件，清理 `%APPDATA%\zebar\webview-cache\loo0ng` 下该包的缓存，再打开。删除前确认实际目录，勿清其他组件缓存。

客户端固定为 `zebar@3.3.1`，通过 `vendor/zebar-3.3.1.js` 本地导入；完整浏览器依赖、来源哈希和许可证均随包提供，`vendor/**` 纳入资源白名单。升级步骤见 [随包客户端](../widget/vendor/README.md)。一条命令安装属于 #6，窗口控件与拖动属于 #7，最终人手验收属于 #8。

## #4 错误隔离与设置指引

扫描输出新增 `设置错误`：正常为 `null`，失败为 `{"类别": "…", "原因": "…"}`。
四种类别是 `文件不存在`、`不是 JSON`、`缺少根目录`、`根目录为空`；另对不可读设置和无效路径数组给出明确错误。
原因含实际设置路径、可填写的 JSON 形状及 Windows 路径提示。设置失败仍返回成功的 JSON 输出，案件数为零，页面显示指引并继续每五秒重试；修好后指引消失。`--根` 继续绕过设置。

坏 JSON、无法读取的视图、不支持的版本以及不存在的根目录均隔离到 `读不出`，页面置于正常案件下面。版本原因保留实际版本和“只认 2”。

- Python 3.9.25：全套 15 条 unittest 通过，编译检查和 `git diff --check` 通过；仓库无独立类型检查器。
- 无法读取的用例在 Windows 使用真实文件独占句柄，CLI 在独立进程中读文件；非 root 的 POSIX 使用文件权限，不模拟扫描内部函数。
- Windows Zebar 3.3.1 自动宿主验证：使用此前种子回放视图的临时副本，将其中一份改成坏 JSON，确认它移到最底下，其余两行不变。
- 四种设置错误逐一在宿主显示路径和示例；恢复有效设置后，三行恢复且提示消失。截图已检查，无文本截断。验后恢复原设置与正常宿主启动，保留更新的组件包。
- 2026-09-17 用户确认两项人手验收：坏视图场景中两案正常，坏案在下方显示读不出；移除设置后，设置文件路径和 JSON 填写示例均显示。#4 验收完成。
- 双轴审查：Standards 无发现；Spec 无代码缺陷，人手验收缺口已由上述用户确认闭合。
- 现场反馈曾出现“只有读不出、另两案不显示”。核查恢复后的原设置：所指根目录不存在，CLI 返回零案和根目录错误。重新固定合成根目录后 CLI 返回两案与一个坏 JSON 错误；后续人手验收逐步确认后再切场景，避免自动切换与恢复设置混淆观察。
- 人手验收结束后，按字节核对恢复原设置，还原临时合成视图；保留更新的组件包。原设置指向不存在的根目录，恢复后的相应提示是预期状态。
