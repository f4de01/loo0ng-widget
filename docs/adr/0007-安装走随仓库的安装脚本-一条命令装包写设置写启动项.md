# 安装走随仓库的安装脚本：一条命令装包、写设置、写启动项，再跑一次就是更新

到 0.3.1 为止，README 教律师整行粘贴三段单行命令（装包、写 Zebar 启动项、建桌面快捷方式），每段几百个字符；设置文件 `~/.loo0ng/卡片设置.json` 要自己建、自己把 Windows 路径转成 `/`；更新另有三步（挪开旧包、清缓存、重装）。对律师来说这页太长，也容易在哪一步漏掉。

裁定（#33）：仓库根放两份安装脚本，`install.ps1` 给 Windows、`install.sh` 给 mac，README 上各只剩一条短命令（`irm … | iex`、`curl … | sh`）。脚本一次做完：前提检查（Python 3.9 以上、Zebar 装没装）；下载公开仓库 `main` 的归档并装到 `~/.glzr/zebar/loo0ng/`，已装即原地更新；设置文件不存在时问一次案件根目录写一份，存在就一个字不动；按 ADR-0006 把 Zebar 的启动项写成只有案件卡片；可选桌面快捷方式；装完把 Zebar 打开。更新只清这个包的 WebView `Cache` 与 `Code Cache`，本地存储留着，所以呈现偏好（窗口位置、停在哪一页、已归档的案件）不再随更新丢失。

脚本不是组件包的一部分，不进 `widget/`，也不进 `includeFiles`；它写的东西（包目录、设置文件、Zebar 设置、快捷方式）都是律师照 README 跑一条安装命令的结果，与 ADR-0006 同一类，不碰硬边界 2，也不碰不变量 4：唤起脚本照旧只找宿主、调一条命令。

可测的缝：两份脚本都认几个环境变量（`LOO0NG_HOME`、`LOO0NG_SOURCE`、`LOO0NG_ZEBAR`、`LOO0NG_HOST=0`、`LOO0NG_ROOT`、`LOO0NG_SHORTCUT`），测试把用户目录换成临时目录、包来源换成从工作树打出来的本地 zip、宿主换成临时目录里的假文件、并且不碰 Zebar 进程，真起子进程跑脚本，与唤起脚本的测试同一条原则：**测试一次都不许碰本机真装的 Zebar**。

两个实现细节是裁定的一部分：

- `install.ps1` 是**不带 BOM** 的 UTF-8，整个过程包在一个函数里、失败只 `return`，结果留在 `$ok`。原因：`irm` 按 raw.githubusercontent.com 给的 `charset=utf-8` 解码，带 BOM 反而会在 `iex` 时多出一个坏记号；而 `iex` 里的 `exit` 会把律师的 PowerShell 窗口一起关掉。代价是本地不能用 `-File` 跑它（Windows PowerShell 5.1 会按 ANSI 读、汉字全坏），测试与开发者都像律师那样走 `iex`。
- Windows 上探测 Python 要先放宽 `$ErrorActionPreference`：微软商店的 0 字节占位往 stderr 写一句、以 9009 退出，Stop 模式下这一句本身就是终止性错误（#32 的同一件事换个地方再撞一次）；探到占位就退到 `py`，快捷方式指向探到的那个解释器旁边的 `pythonw`。

考虑过：上 Zebar 官方市场，律师在 Zebar 设置里点安装——设置文件与启动项仍要另写，且发布流程在仓库之外，暂不走；只把下载源换成 GitHub Releases 的压缩包——改动最小，但三段长命令与手建设置的问题一个没解。这两条都没被否死，日后可以叠在脚本之上。
