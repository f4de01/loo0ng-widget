# 原型：这张卡片在 Zebar 里到底跑不跑得起来

## 这是什么，答的是哪个问题

一次性的、答题用的代码，不是实现。它只答三个问题：

1. 组件包装得上吗，卡片出得来吗？
2. 扫根目录认得出两个以上案件吗？`图视图.json` 变了，卡片跟得上吗？跟的方式该用轮询还是文件监听？
3. 关掉一张卡，宿主里其他组件与其他案件的卡片会不会跟着倒？

呈现不是这里的问题：怎么排版、显示哪几格、点开是什么，已经推后了。所以页面长什么样在这里不算数，
它只负责把状态摊出来给人看。

写法上的一个偏离：做原型这件事本来给了两条路，一条是给非开发者点按的状态机演示，一条是几版界面
摆在一起挑。这三个问题哪条都不正对，它们是宿主机制题。取的是第一条路的骨架里最值钱的两条规矩：
**纯模块与页面分开**（`aggregate.js` 不碰 DOM，答完题整块抬进实现），**每次动作后把完整状态摊在
页面上**。没有为了凑格式编造律师要点的按钮。

## 怎么跑

```
python 原型/造喂料.py       # 现生三个合成案件工作区，写好设置文件
python 原型/探针.py         # 可选：排障通道，页面把处境报到 127.0.0.1:8787
```

然后把 `卡片/` 里的文件拷进 `~/.glzr/zebar/loo0ng/`，开：

```
zebar.exe start-widget-preset --pack loo0ng --widget-name 案件卡片 --preset 默认
```

没装宿主也能看页面：`python 原型/造喂料.py` 之后用任意静态服务器开 `卡片/index.html`，它会退到
读 `stub.json` 的桩模式。

喂料全是合成的：由 loo0ng-skills 的种子回放出来，当事人一律写甲乙丙，没有任何真实案件。

## 答案

### 一、装得上，卡片出得来

组件包放进 `~/.glzr/zebar/<包名>/`，`start-widget-preset` 能开出窗口，页面能加载，模块脚本能执行，
`window.__ZEBAR_STATE` 在。

**踩到的坑（卡了最久的一处）**：`zpack.json` 里的 `includeFiles` 不是"额外附带的文件"，它是**资源
服务器允许发出去的文件清单**。`htmlPath` 指的那个文件如果没被它覆盖，Zebar 的资源服务器直接回
500，窗口里是一张 Rocket 的报错页，没有任何别的线索。照官方 starter 包写成通配符最稳：

```json
"htmlPath": "./index.html",
"includeFiles": ["*.html", "*.js", "*.py"]
```

**没有验证的一条**：包里的文件名现在全是 ASCII。中文文件名能不能用，**没有单独验过** ——
改名和修 `includeFiles` 是挤在一起做的，500 的真正原因是后者。要用中文名得自己再验一次。

**另一个坑**：WebView2 有磁盘缓存，改完代码要清 `%APPDATA%\zebar\webview-cache\<包名>`，否则看到的
还是上一版（包括上一版的报错页）。

### 二、扫得出多个案件，也跟得上变化；用轮询，不必上文件监听

- 一个根目录下三个合成工作区，卡片扫出三个案件。
- 往根目录里拷进第四个工作区，**下一轮轮询（5 秒内）就出现在卡片上**，不必重启、不必重新设置。
- 用图引擎确认了 `在办中` 的一个节点，`图视图.json` 的 `生成时间` 从 22:10:29 变成 22:27:10，
  两张卡片都在一轮内跟上。

**量出来的成本**：扫描本身 0 至 2 毫秒（四个案件）；整个来回约 50 毫秒，几乎全是起一次 python 的
开销。5 秒一轮等于千分之一的占用。**结论：轮询够用，不必为此引入文件监听或常驻进程。**

`shellExec` 的白名单按 `program` 加 `argsRegex` 走，实测可用，两条都要写：

```json
{ "program": "python",  "argsRegex": ".*scan\\.py.*" },
{ "program": "python3", "argsRegex": ".*scan\\.py.*" }
```

**宿主判断**要看 `window.__ZEBAR_STATE`（拿不到再退到 `sessionStorage` 里的 `ZEBAR_STATE`），
这是 Zebar 客户端自己认的那两处。按 Tauri 的内部标记去认是错的，会让页面悄悄走进桩模式，
什么错都不报。

`import * as zebar from 'https://esm.sh/zebar@3.3.1'` 在宿主里可用，官方 starter 包也是这么干的。
**离线能不能用没验证**：esm.sh 的 `?bundle` 仍然把 Tauri 与 luxon 拆成外部请求，想整包带走得另想办法。

### 三、关掉一张卡，别的不受影响

开两张卡（widget-1、widget-2），关掉 widget-2 之后，widget-1 的轮询一拍没停，宿主进程也活着。

**顺带发现**：同一个组件加同一个预设只开一个实例，第二次开是空操作。要两张卡就得两个预设。

## 要回头改裁定的一处

裁定里写的是"律师在组件设置里填一到几个根目录"。实际上 Zebar 的组件配置里**没有**给组件自定义
设置的地方，`zpack.json` 的那套字段是固定的。所以根目录只能落在包外的一个设置文件里，现在放的是
`~/.loo0ng/卡片设置.json`（`~/.loo0ng/` 这个家已经因为个人预设图存在了）。裁定那半句要按这个改。

## 还没答的

- **拖得动吗、卡片长什么样**：这两样只能用眼睛看，机器这边只能确证数据链路。`index.html` 的表头
  带了 `data-tauri-drag-region`，没有人工确认过它真的拖得动。
- **mac 那一侧**：一次都没跑过。按裁定，Windows 通过即交一版，mac 那次并进交付。
- **离线**：见上，远程 import 的离线退路没定。

## 这里面哪些是脚手架，实现时要删

- `原型/探针.py` 与 `index.html` 里那段探针（页面把处境 POST 到 127.0.0.1:8787）。
- `scan.py` 里的 `记一行` 与 `--记`、`--标`：靠一个开关文件 `%TEMP%/loo0ng-扫描.log` 决定写不写。
  卡片在宿主里跑的时候看不见 stdout，这是当时唯一能问出"脚本到底跑没跑"的办法。
- `read.js` 里的桩模式与 `stub.json`。
- 页面里默认就点开轮询那一行。

抬进实现的只有一样：`aggregate.js`。它不碰 DOM、不读文件、不起进程，输入是引擎算好的视图，
输出是卡片上那一行；只做计数、排序、取第一个，判定一概不做。
